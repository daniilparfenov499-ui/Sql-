СПОРТКОМПЛЕКС
Информационная система управления спорткомплексом
Курсовой проект по дисциплине "Разработка и защита баз данных"

СОСТАВ ПРОЕКТА

Проект включает четыре компонента:

1. Аналитика
   Файл: Аналитика_БД_Спорткомплекс.txt
   Содержание: описание предметной области, функции системы, ключевые
   показатели (KPI), требования к системе, статистика базы данных.

2. ER-диаграмма (концептуальная модель)
   Файл: ER_диаграмма_концептуальная.png
   Содержание: диаграмма сущностей и связей предметной области
   (15 сущностей, связи с указанием кратности).

3. Реляционная модель (физическая модель)
   Файлы: sports_complex.sql, Реляционная_модель_физическая.png
   Содержание: SQL-схема для SQLite (CREATE TABLE, индексы, представления,
   тестовые данные) и схема связей таблиц с типами данных и ключами.

4. База данных SQLite
   Файл: sports_complex.db
   Содержание: готовая база данных (16 таблиц, 25 индексов, 4 представления,
   77 тестовых записей).

КАК ОТКРЫТЬ БАЗУ ДАННЫХ

Вариант 1. DB Browser for SQLite
1. Скачайте программу с сайта https://sqlitebrowser.org/
2. Откройте программу, выберите "Файл" -> "Открыть базу данных"
3. Укажите файл sports_complex.db

Вариант 2. Командная строка
   sqlite3 sports_complex.db
   sqlite> .tables
   sqlite> SELECT * FROM athletes;
   sqlite> .quit

Вариант 3. Python
   import sqlite3
   conn = sqlite3.connect('sports_complex.db')
   cursor = conn.cursor()
   cursor.execute('SELECT * FROM athletes')
   print(cursor.fetchall())
   conn.close()


ПРИМЕРЫ ЗАПРОСОВ

Все активные подписки:
  SELECT * FROM v_active_subscriptions;

Расписание тренировок:
  SELECT * FROM v_weekly_training_schedule
  WHERE session_date >= DATE('now');

Результаты соревнований:
  SELECT * FROM v_competition_results
  ORDER BY match_date DESC;

Общий доход:
  SELECT SUM(amount) AS total_revenue
  FROM payments WHERE status = 'успешно';

Активные спортсмены:
  SELECT * FROM athletes WHERE status = 'активный';


ХАРАКТЕРИСТИКИ ПРОЕКТА

  Таблиц:                   16
  Столбцов:                 более 150
  Первичных ключей:         16
  Внешних ключей:           30
  Индексов:                 25
  Уникальных ограничений:   более 10
  CHECK-ограничений:        более 15
  Представлений:          4

Нормализация: схема приведена к нормальной форме Бойса-Кодда (НФБК),
частичные и транзитивные зависимости отсутствуют.

Целостность данных: для каждой таблицы задан первичный ключ, все связи
оформлены внешними ключами, для критичных полей заданы ограничения
CHECK, UNIQUE и NOT NULL.

Производительность: создано 25 индексов на часто используемых полях,
определены 4 представления для типовых запросов.
